电池手册

这份手册讲这块板子上电池相关的全部代码：怎么读电压、读数怎么得来、电池供电时怎么开机和关机、读数不准怎么校准。所有内容都对着仓库里的源码写，改过的代码请以源码为准。

数据流

一次电压读数从引脚到屏幕，走的是这条链：

GPIO8 ──▶ ADC 12 bit ──▶ analogReadMilliVolts() ──▶ ×3.0 ÷ 0.990476
                                                        │
   屏幕上 "Battery Voltage" 文本框 ◀── BAT_analogVolts ◀─┘

中间没有任何缓存或滤波：BAT_Get_Volts() 每被调用一次就真的采一次 ADC。

3电压怎么算

核心就这五行，在 BAT_Driver.cpp:10：

float BAT_Get_Volts(void)
{
  int Volts = analogReadMilliVolts(BAT_ADC_PIN);   // 毫伏
  BAT_analogVolts = (float)(Volts * 3.0 / 1000.0) / Measurement_offset;
  return BAT_analogVolts;
}

把公式单独拎出来：

电池电压 = (ADC 毫伏 / 1000) × 3.0 ÷ 0.990476

两个常数各管一件事：

  • × 3.0 —— 板上有个 1/3 分压，ADC 引脚看到的只有电池电压的三分之一，所以要乘回去。算一下量程：ADC 引脚最高约 3.3 V，乘 3 就是 9.9 V 的测量上限，够用。
  • ÷ 0.990476 —— 出厂校准，等效于把读数再抬高约 1%。系数小于 1 做的是除法，读数变大。

用的是 analogReadMilliVolts() 而不是 analogRead()。前者会拿芯片里烧好的 eFuse 校准曲线把原始值换算成毫伏，比原始码值准得多，代价是每次调用多花几十微秒。BAT_Init() 里那句 analogReadResolution(12) 对 analogReadMilliVolts() 其实没有影响，真正起作用的是 ADC 自己的校准。

4最小用法

自己写个新程序，把电池电压读到串口：

#include "BAT_Driver.h"

void setup() {
  Serial.begin(115200);
  BAT_Init();                        // 只调一次
}

void loop() {
  float v = BAT_Get_Volts();          // 真采一次 ADC
  Serial.printf("%.2f V\r\n", v);

  // 或者不动 ADC，只拿最近一次的结果：
  // float cached = BAT_analogVolts;

  delay(1000);
}

本工程里实际是怎么接的

  • LVGL_Arduino.ino:42 在 setup() 里调 BAT_Init()。
  • LVGL_Arduino.ino:20 在 DriverTask 里调 BAT_Get_Volts()。这个任务钉在核心 0，优先级 3，循环里 vTaskDelay(pdMS_TO_TICKS(100))，所以采样率约 10 Hz。
  • LVGL_Example.cpp:324 把 BAT_analogVolts 格式化成 %.2f V，写进界面上那个 BAT_Volts 文本框，标签是 "Battery Voltage"。刷新它的是 LVGL 定时器 example1_increase_lvgl_tick，周期也是 100 ms。

写代码的人分在两个任务里：BAT_analogVolts 由核心 0 的采样任务写，被核心 1 上跑的 LVGL 任务读。一个 4 字节对齐的 float 在 Xtensa 上读写是单条指令，不会出现读到一半的脏值，所以这里不需要加锁。如果以后换成 double 或结构体，就得自己加临界区了。

开机后的头几秒

Driver_Loop() 在整个 setup() 的最后才创建 DriverTask。在那之前没人调 BAT_Get_Volts()，屏幕上的电压会显示 0.00 V。这是正常的，不是没读到电池。

5开机与关机

这块板子没有机械电源开关。按下 PWR 键只是让硬件临时给电，真正"记住"这个开机动作的是固件——它把 GPIO7 拉高，用一个软锁存电路把电源维持住。GPIO7 一拉低，电就断了，MCU 想拦都拦不住。

开机

  1. 1

    接上电池，按住 PWR 键不放。硬件电路此时给整机供电，芯片开始启动。

  2. 2

    固件跑到 PWR_Init()，检测到按键还按着（PWR_KEY_Input_PIN 读到低电平），于是把 PWR_Control_PIN 拉高，锁存供电。

  3. 3

    松开 PWR 键。因为锁存已经建立，系统继续运行。

注意

第 2 步必须在松手之前完成。如果固件卡在启动早期、或者被改坏了，松开按键的瞬间就会断电，表现为"按一下亮一下就灭"。遇到这个现象，先查 PWR_Init() 有没有被调用、GPIO7 有没有被别的代码占用。

关机

长按 PWR 键 3 秒。链路是这样走的：

按住 PWR 键 3 s
   └─▶ OneButton 触发 LongPressStart
         └─▶ Button_Driver.cpp 的回调把 PWR_KEY_State 设为 LongPressStart
               └─▶ PWR_Loop() 读到这个状态
                     └─▶ Shutdown()
                           └─▶ digitalWrite(PWR_Control_PIN, LOW)  // 断电

3 秒这个阈值在 Button_Driver.cpp:16 的 button2.setLongPressIntervalMs(3000)。PWR_Loop() 被 DriverTask 每 100 ms 调一次，所以从松手到真正断电最多还有 100 ms 的延迟，看起来就是"松手后灯还亮了一下"。

相应的代码

void PWR_Init(void) {
  pinMode(PWR_Control_PIN, OUTPUT);
  digitalWrite(PWR_Control_PIN, LOW);
  vTaskDelay(100);
  if(!digitalRead(PWR_KEY_Input_PIN)) {          // 按键被按住
    digitalWrite(PWR_Control_PIN, HIGH);         // 锁存供电
  }
}

void Shutdown(void) {
  digitalWrite(PWR_Control_PIN, LOW);           // 切断锁存，整机断电
  LCD_Backlight = 0;
}
这是个坑

Shutdown() 里那句 LCD_Backlight = 0 只改了变量，并没有调用 Set_Backlight()，背光 PWM 其实一点没变。因为紧接着就断电了，平时看不出来。但千万别把它当"熄屏休眠"用——它唯一真正的作用是拉低 GPIO7。想要熄屏，单独调 Set_Backlight(0)。

6电压换算电量

代码里只有电压，没有百分比。要显示电量，得自己按单节锂电的电压曲线换算。下面这条刻度是开路电压的粗略对应，范围取 3.30 V 到 4.20 V：

3.303.703.904.20 V
3.30–3.70 V 该充电了 3.70–3.90 V 还能用 3.90–4.20 V 电量充足
电压大致电量说明
4.20 V100%满电。充电刚结束时会是这个值。
4.00 V80%
3.85 V60%
3.70 V40%标称电压。
3.60 V25%
3.50 V10%WiFi 发射时可能已经触发欠压复位。
3.30 V0%放电截止。再低会伤电池。

别拿它当精确电量

  • 带载时读数会明显偏低。WiFi 或屏幕背光一拉电流，电压瞬间掉几十到上百毫伏，采到的值跟着掉。
  • ESP32-S3 加屏幕在 3.4 V 以下就容易欠压复位。实际能用的"没电点"比表里的 3.30 V 高，别等它掉到 3.3 V 才提醒充电。
  • 临时负载、温度、电池新旧都会让曲线偏移。判断"还能不能撑"够用，判断"剩余多少分钟"不够用。

要更稳的读数，就在 BAT_Get_Volts() 外面套一层多次采样取平均，比如连读 8 次去掉最大最小再平均。Radio 空闲的时候采样噪声最小。

7校准

读数差个 1~2% 是分压电阻的误差，换个电池、换块板子都可能不一样，需要重标一次 Measurement_offset。整个过程五分钟：

  1. 1

    接上电池，让板子跑起来，静置一会儿别做重活。用万用表直接量电池两端的真实电压，记作 V_real。

  2. 2

    同时读固件显示的电压，屏幕上的 "Battery Voltage" 或串口打印的 BAT_analogVolts，记作 V_fw。两个读数要尽量在同一时刻取。

  3. 3

    套公式算新系数：

    新 offset = 0.990476 × V_fw ÷ V_real
  4. 4

    把结果写回 BAT_Driver.h:5 的 Measurement_offset，重新编译烧录，再对一次表。

举个例子

万用表读到 3.90 V，固件显示 3.95 V，说明固件读高了：

新 offset = 0.990476 × 3.95 ÷ 3.90 ≈ 1.0032

把 Measurement_offset 改成 1.0032。注意系数的作用是除法，想让它读小就要把系数调大——跟直觉相反，改的时候别弄反。

校准要在轻载下做。如果校准时开着 WiFi 传输，会把负载压降一起标进去，等设备闲下来读数就偏高了。

8排查表

现象先查什么
一直显示 0.00 V BAT_Get_Volts() 有没有人调。BAT_analogVolts 初值就是 0，没人采样就一直是 0。开机头几秒显示 0 是正常的，见第 4 节。
读数比万用表高或低一点 正常的分压电阻误差。按第 7 节重新校准。
读数跳得厉害 WiFi / BLE 发射噪声。多次采样取平均；采样时机避开射频活动。
没接电池也读得出值 引脚悬空时会采到噪声。要判断"有没有电池"，得先看读数是否落在合理区间，光看是不是 0 不够。
长按 PWR 键关不了机 PWR_Loop() 有没有被周期调用。DriverTask 挂了的话，长按状态没人处理，就永远关不了机。
松手就断电 PWR_Init() 没跑到，或者 GPIO7 被别的代码拉低了。见第 5 节。
电压明显不对，差好几倍 分压比不是 1:3。见第 9 节。

9换板子改什么

这套代码来自微雪 ESP32-S3-LCD-2.8 的例程，搬到别的板子上要动这几处：

情况改哪里
采样引脚不是 GPIO8 BAT_Driver.h:4 的 BAT_ADC_PIN
分压比不是 1:3 BAT_Driver.cpp:13 里的 3.0。常见的还有 1:2（改成 2.0）。改完必须重新按第 7 节校准。
PWR 键或锁存脚不同 PWR_Key.h 的 PWR_KEY_Input_PIN 和 PWR_Control_PIN
板子没有软锁存电路 删掉 PWR_Init() 里的 GPIO7 逻辑，保留按键供其他用途。别让代码去驱动一个不存在的锁存脚。
